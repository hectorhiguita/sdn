Concepto Central

¿Qué es la Virtualización de Red (NV)?

✕ Red Tradicional (física)

Switches y routers físicos — hardware dedicado
Cambios requieren cableado manual y downtime
Semanas para provisionar una nueva VLAN
Seguridad depende de la topología física

✓ Red Virtualizada (NSX)

Switches, routers y firewalls en software
Desacoplado del hardware físico — cero cambios
Red = código: crear/mover/eliminar en segundos
Seguridad sigue a la VM, no a la VLAN
"Con NSX, la red es código. Se puede crear, mover, clonar y eliminar junto con las máquinas virtuales."

↕ Tráfico Norte-Sur
Entra y sale del datacenter desde internet. El firewall perimetral lo controla. Los firewalls tradicionales son muy buenos aquí.
↔ Tráfico Este-Oeste
Movimiento lateral entre servidores dentro del datacenter. El firewall perimetral no lo ve. Si un atacante entra, se mueve libremente entre VMs de la misma VLAN.
⚠ El Problema
Un servidor comprometido puede propagarse a toda la VLAN. Este es el vector principal de ransomware moderno. NSX resuelve exactamente esto.

Componente Clave

NSX Distributed Firewall (DFW) — El Guardián de cada VM

El DFW vive en el kernel del hipervisor y aplica políticas en la vNIC de cada VM — no en la red física.

🔍 Capas L2 – L7
Inspección stateful desde la capa de enlace hasta aplicación. Soporta reglas por puerto, protocolo y aplicación.
🚀 Sigue a la VM (vMotion)
Las reglas DFW se mueven con la VM durante vMotion. La seguridad no depende de la ubicación física.
🏷 Políticas por identidad
Reglas basadas en tags, nombre de VM, sistema operativo, grupo de seguridad — no solo IP/puerto.
⚡ Sin hair-pinning
El tráfico no sale al firewall físico y vuelve. Inspección local en el hipervisor = baja latencia, line-rate.
Analogía: si el firewall perimetral es el guardia de la puerta del edificio, el DFW es un guardaespaldas personal que acompaña a cada servidor a donde vaya.

Modelo de Seguridad

Principios de Zero Trust

"Nunca confiar · Siempre verificar · Asumir que ya hubo una brecha" — John Kindervag, Forrester 2010

🔐
Verificar explícitamente
Autenticar siempre basándose en todos los datos disponibles: identidad, dispositivo, ubicación.
NSX aplica esto en cada paquete de red con contexto completo.
🎯
Mínimo privilegio
Solo el acceso mínimo necesario para cada tarea. Políticas granulares por VM, por aplicación.
Modelo whitelist: todo está denegado por defecto.
🛡
Asumir brecha
Diseñar como si el atacante ya estuviera dentro. Minimizar radio de explosión.
El DFW bloquea el movimiento lateral inmediatamente.
NSX implementa Zero Trust mediante microsegmentación, DFW distribuido y políticas basadas en identidad

Sección 03EXP 03
Caso Práctico

Contención de Ransomware con NSX

PASO 1 ⚠
Infección inicial
El ransomware entra por un email de phishing al Web Server (tráfico Norte-Sur). El firewall perimetral lo permite porque viene disfrazado de tráfico legítimo.
PASO 2 →
Intento de movimiento lateral
El ransomware escanea la red local. Encuentra el App Server y la Base de Datos en la misma red. En una red tradicional, simplemente se conecta y los cifra.
PASO 3 🛡
NSX DFW bloquea
El DFW en la vNIC deniega el tráfico no autorizado Este-Oeste. No existe regla que permita Web→DB por puerto 445 (SMB). La política default deny bloquea el paquete.
PASO 4 ✓
Contención exitosa
Solo el Web Server comprometido. App Server y Base de Datos intactos. NSX Intelligence genera el flow log con el rastro exacto del ataque.
"Sin NSX: un servidor comprometido puede cifrar todo el datacenter. Con NSX: un servidor comprometido es exactamente eso, solo uno."

Adopción en la Industria

Adopción en la Industria — vDefend y VMware Cloud Foundation

Desde 2023 (Broadcom), el NSX DFW se rebautizó como VMware vDefend · integrado en VMware Cloud Foundation (VCF)

🏦
Banca y Finanzas
Aislamiento de sistemas de pagos. Cumplimiento PCI-DSS. Protección de datos de clientes y tarjetas de crédito.
🏥
Salud (Healthcare)
Protección de registros médicos electrónicos. Cumplimiento HIPAA. Segmentación de dispositivos IoT médicos.
🏛
Gobierno y Defensa
Zonas de seguridad clasificadas. Cumplimiento NIST. Redes Zero Trust para datos sensibles del estado.
📡
Telecomunicaciones
Segmentación de infraestructura 5G. NFV (Network Function Virtualization). Multi-tenant seguro para slices de red.

Cierre

Conclusiones

01
NSX transforma la red en código: flexible, automatizable y segura por diseño. El Software-Defined Data Center en su forma más completa.
02
La microsegmentación resuelve el tráfico Este-Oeste que los firewalls perimetrales no pueden controlar. Un servidor comprometido ya no puede propagarse.
03
Zero Trust con NSX no es teoría — el DFW (vDefend) lo implementa en producción en miles de empresas: banca, salud, telecomunicaciones y gobierno.
En un mundo donde los ataques de ransomware cuestan millones por incidente,
¿puede su empresa permitirse no tener microsegmentación?
