Concepto Fundamental

¿Qué es la Virtualización de Red (NV)?

Red Tradicional (física)

Switches y routers físicos
Cambios requieren cableado manual
Semanas para provisionar una VLAN
Seguridad depende de la topología física
Alta dependencia del hardware

Red Virtualizada (NSX)

Switches, routers y firewalls en software
Desacoplado del hardware físico
Red = código: crear/mover/eliminar en segundos
Seguridad sigue a la VM, no a la VLAN
Automatizable vía API

El Problema Central

Tráfico Norte-Sur vs. Este-Oeste

🌐 INTERNET
↕ Norte-Sur
✔ Firewall lo ve

↓

⇄
App
⇄

↔ Este-Oeste — el firewall NO lo ve

Tráfico Norte-Sur ✔
Entra/sale del datacenter. El firewall perimetral lo controla. Los firewalls tradicionales son muy buenos aquí.
Tráfico Este-Oeste ✗
Movimiento lateral entre servidores dentro del datacenter. Nunca sale → el firewall perimetral no lo ve. Un atacante que ya está dentro se mueve libremente.
Este es el vector principal del ransomware moderno. NSX resuelve exactamente este problema.

Componente de Seguridad Clave

NSX Distributed Firewall (DFW)

El DFW vive en el kernel del hipervisor y aplica políticas en la vNIC de cada VM — no en la red física.

🔍 Capas L2 → L7
Inspección stateful desde la capa de enlace hasta aplicación. Soporta reglas por puerto, protocolo y aplicación.
🚚 Sigue a la VM (vMotion)
Las reglas DFW se mueven con la VM durante vMotion. La seguridad no depende de la ubicación física.
🏷️ Políticas por identidad
Reglas basadas en tags, nombre de VM, sistema operativo, grupo de seguridad — no solo IP/puerto.
⚡ Sin hair-pinning
El tráfico no sale al firewall físico y vuelve. Inspección local en el hipervisor = baja latencia, line-rate.
NSX Distributed Firewall (DFW) — El Guardián de cada VM EXP 02
El Concepto Clave

Microsegmentación

Sin microsegmentación

🏢
Un edificio con solo un guardia en la puerta
Una vez dentro → acceso libre a todo. Una VM comprometida puede llegar a todas las demás.

Con microsegmentación NSX

🏨
Un hotel: cada habitación tiene su propia cerradura
Cada VM tiene políticas únicas de acceso. Un servidor comprometido queda aislado automáticamente.
Microsegmentación: divide el datacenter en zonas de seguridad hasta el nivel individual de cada VM, con políticas únicas para cada una.
Microsegmentación — El Concepto Clave EXP 02
Modelo de Seguridad

Principios de Zero Trust

"Nunca confiar · Siempre verificar · Asumir que ya hubo una brecha"
🔒
Verificar explícitamente
Autenticar siempre basándose en todos los datos disponibles: identidad, dispositivo y ubicación.
→ NSX: cada paquete verificado con contexto completo
📐
Mínimo privilegio
Solo el acceso mínimo necesario para cada tarea. Políticas granulares por VM, por aplicación, por usuario.
→ NSX: modelo whitelist — todo denegado por defecto
🛡️
Asumir brecha
Diseñar como si el atacante ya estuviera dentro. Minimizar radio de explosión con microsegmentación.
→ DFW bloquea el movimiento lateral inmediatamente
✔ NSX implementa Zero Trust mediante microsegmentación, DFW distribuido y políticas basadas en identidad

Sección 03 EXP 03
Caso Práctico

Contención de Ransomware con NSX

PASO 1 — Infección inicial
Phishing → Web Server
El ransomware entra por email de phishing. El firewall perimetral lo permite porque parece tráfico legítimo de internet.
PASO 2 — Intento lateral
Busca App Server y DB
El ransomware escanea la red local. En red tradicional, sin control E-O, se conecta y cifra todos los servidores.
PASO 3 — NSX DFW bloquea
Política Default Deny actúa
El DFW en la vNIC deniega el tráfico no autorizado Este-Oeste. No existe regla que permita Web→DB por puerto 445.
PASO 4 — Contención exitosa
Solo el Web Server comprometido
App Server y Base de Datos intactos. NSX Intelligence genera alerta con el flow log del intento de ataque.
Según Mandiant/CrowdStrike, el tiempo promedio de permanencia de un atacante es 21 días. La microsegmentación convierte ese mes de movimiento libre en segundos de contención.

Cada VM está protegida individualmente. El atacante no puede saltar capas aunque ya esté dentro de la red.

Análisis Comparativo

Red Tradicional vs. VMware NSX

Aspecto Red Tradicional VMware NSX
Superficie de ataque Toda la VLAN expuesta si hay una brecha Solo la VM comprometida, el resto aislado
Tiempo de contención Horas o días (detección manual) Segundos (DFW aplica políticas automáticamente)
Cambios de red física Re-cablear, nueva VLAN, downtime Cero cambios en la red física subyacente
Visibilidad E-O Ninguna — tráfico lateral invisible 100% — NSX registra cada flujo Este-Oeste
Cumplimiento normativo Difícil auditar en red plana Políticas documentadas para GDPR, HIPAA, PCI-DSS
Automatización Reglas manuales en firewalls físicos API REST — políticas como código (IaC)

Cierre

Conclusiones

1
NSX transforma la red en código: flexible, automatizable y segura por diseño. El Software-Defined Data Center en su forma más completa.
2
La microsegmentación resuelve el problema del tráfico Este-Oeste que los firewalls perimetrales no pueden controlar. Un servidor comprometido ya no se propaga.
3
Zero Trust con NSX no es teoría académica — el DFW (vDefend) lo implementa en producción en miles de empresas de banca, salud, telecomunicaciones y gobierno.
4
El resultado: menor superficie de ataque, contención automática de amenazas y cumplimiento normativo simplificado (GDPR, HIPAA, PCI-DSS).
¿Puede su empresa permitirse no tener microsegmentación en un mundo donde los ataques de ransomware cuestan millones por incidente?
